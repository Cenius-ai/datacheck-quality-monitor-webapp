# Installing Datacheck Quality Monitor

## Prerequisites

| Requirement | Version | Notes |
|---|---|---|
| Python | 3.11+ | system interpreter; no virtualenv required |
| pip | 22+ | upgraded automatically by `install.sh` |
| SQLite | 3.35+ | shipped with Python (`sqlite3`); the file lives in the project root |
| OpenSSL | any | optional — `install.sh` generates the session secret with Python instead |
| python-dotenv | 1.0.1 | installed from `requirements.txt`; lets the Flask CLI read `.flaskenv` |

No database server, message broker, Node toolchain or Docker is needed. The app makes no
outbound network calls at runtime; the Manrope webfont is vendored in
`datacheck/static/fonts/`.

## 1. Install the project dependencies

```bash
sh install.sh
```

That one command:

1. upgrades `pip`, `setuptools` and `wheel`,
2. installs `requirements.txt` (Dash, Flask, Plotly, SQLAlchemy, Werkzeug, pytest),
3. writes `.env` with a freshly generated `SESSION_SECRET` (only if `.env` is missing),
4. seeds the demo database (idempotent) — 3 datasets × 500 rows, 5 rules each, 63 runs,
5. imports the app once to prove the entrypoint loads,
6. exits without starting a server.

Prefer to run the steps by hand?

```bash
python3 -m pip install --upgrade pip setuptools wheel
python3 -m pip install -r requirements.txt
python3 -m datacheck.seed          # step 3: seed (never starts a server)
```

## 2. Start the dashboard

```bash
python3 app.py
```

The server binds `0.0.0.0` and reads `PORT` (default **8050** — the Dash default):

```bash
PORT=9000 python3 app.py
```

Or start it with the Flask CLI (the module exposes one WSGI app as `server`, and
`.flaskenv` sets `FLASK_APP=app`, `FLASK_RUN_HOST=0.0.0.0`, `FLASK_RUN_PORT=5000`):

```bash
flask run                                  # 0.0.0.0:5000
flask run --host 0.0.0.0 --port 8050       # or pick your own port
```

Open <http://localhost:8050> → you are redirected to `/login` → sign in with
`cenius@cenius.ai` / `cenius`.

## How to verify the install

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8050/login        # 200
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8050/api/datasets # 401 (no session)
python3 -m pytest                                                           # all green
```

Sign in through the UI and confirm all three tabs render seeded content. Because the schema
and demo data are created on the normal boot path, deleting `datacheck.db` and running
`python3 app.py` again gives you a fresh, fully populated workspace.

## Configuration

Copy `.env.example` to `.env` and adjust. Every variable has a working default — the app
boots with no `.env` at all.

| Variable | Default | Purpose |
|---|---|---|
| `SESSION_SECRET` | generated by `install.sh`, dev fallback in code | signs helper session state |
| `DATABASE_URL` | `sqlite:///./datacheck.db` | SQLAlchemy URL (relative SQLite path) |
| `PORT` | `8050` | HTTP port, bound on `0.0.0.0` |
| `HOST` | `0.0.0.0` | interface to bind |
| `SESSION_COOKIE_NAME` | `datacheck_session` | cookie name |
| `SESSION_TTL_DAYS` | `7` | server-side session lifetime |
| `LOGIN_MAX_ATTEMPTS` | `10` | sign-in attempts per IP/email per window |
| `LOGIN_WINDOW_SECONDS` | `900` | throttle window |
| `ROWS_PER_DATASET` | `500` | seeded source rows per dataset |
| `HISTORY_RUNS` | `21` | seeded daily runs per dataset |
| `MAX_FAILURE_SAMPLES` | `20` | failing-row samples stored per rule per run |

## Re-seeding

```bash
python3 -m datacheck.seed      # idempotent: existing datasets/runs are left alone
rm datacheck.db && python3 app.py   # nuclear option: fresh database, seeded on boot
```

## Running in production

```bash
export SESSION_SECRET="$(python3 -c 'import secrets;print(secrets.token_hex(32))')"
gunicorn --workers 1 --bind 0.0.0.0:8050 app:server
```

Notes:

- Keep **one worker** (or move sessions/rate limits to a shared store) — the sign-in
  throttle is a SQLite counter and SQLite serialises writes.
- Terminate TLS in front of the app, then set `SESSION_COOKIE_SECURE=True` in
  `datacheck/main.py` (it is deliberately off for plain-HTTP local/preview use — a secure
  cookie over HTTP silently drops every session).
- Delete or rename the seeded demo accounts before exposing the app.
- `datacheck.db*` and `.env` are gitignored; back up the database file if the results matter.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `ModuleNotFoundError: No module named 'dash'` | run `sh install.sh` (or `pip install -r requirements.txt`) |
| `Address already in use` | another process holds `PORT`; stop it or start with a different `PORT` |
| Every page redirects to `/login` | cookies are blocked or `SESSION_SECRET` changed between restarts; clear cookies and sign in again |
| Empty dashboard | `python3 -m datacheck.seed` (or delete `datacheck.db` and restart) |
| Port 8050 unreachable from another machine | make sure you did not override `HOST` with `127.0.0.1` |
